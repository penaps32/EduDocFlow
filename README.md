# EduDocFlow

Веб-приложение для автоматизации оформления, обработки и контроля заявлений и справок студентов образовательной организации.

Проект разработан в рамках дипломной работы по специальности 09.02.07 «Информационные системы и программирование».

## О проекте

EduDocFlow переводит процесс подачи и обработки студенческих обращений в электронный формат.

Студент может выбрать необходимый тип документа, заполнить форму и отслеживать состояние заявки. Сотрудник учебной части получает поступившие обращения, проверяет их, изменяет статус и формирует итоговый документ. Администратор управляет пользователями и доступными типами документов.

Основная цель проекта - сократить количество ручных операций, упростить взаимодействие студентов с учебной частью и сделать процесс обработки обращений более прозрачным.

## Основные возможности

### Студент

* авторизация в системе;
* просмотр личного кабинета и данных профиля;
* просмотр статистики по обращениям;
* выбор необходимого типа документа;
* создание новой заявки;
* динамическая проверка обязательных полей;
* просмотр списка собственных заявок;
* отслеживание текущего статуса;
* просмотр истории обработки;
* обмен уточнениями и комментариями с сотрудником;
* получение сформированного документа после завершения обработки.

### Сотрудник учебной части

* просмотр всех поступивших обращений;
* просмотр сведений о студенте и заявке;
* поиск заявок по номеру, ФИО, электронной почте, группе и типу документа;
* фильтрация заявок по статусу;
* принятие заявки в работу;
* назначение ответственного сотрудника;
* изменение статуса обращения;
* добавление комментариев и уточнений;
* просмотр истории изменений;
* завершение обработки заявки;
* формирование итогового документа.

### Администратор

* просмотр общей статистики системы;
* создание и редактирование пользователей;
* назначение пользовательских ролей;
* включение и отключение учётных записей;
* управление сведениями о студентах;
* создание и редактирование типов документов;
* настройка обязательных полей для разных видов документов;
* изменение доступности и порядка отображения документов.

## Поддерживаемые документы

В начальную конфигурацию системы входят различные виды справок и заявлений:

* справка с места учёбы;
* справка об обучении или периоде обучения;
* справка о размере стипендии;
* справка о проживании в общежитии;
* справка-вызов;
* характеристика с места учёбы;
* заявление на выдачу справки;
* заявление на академический отпуск;
* заявление на перевод;
* заявление на отчисление;
* заявление на восстановление;
* заявление на выдачу дубликата документа;
* заявление на изменение персональных данных.

Администратор может изменять состав доступных документов через интерфейс системы.

## Архитектура проекта

Приложение построено по архитектурному шаблону MVC.

```text
EduDocFlow
└── WebApplication1
    ├── Controllers       # Обработка пользовательских запросов
    ├── Data              # Контекст базы данных и инициализация
    ├── Migrations        # Миграции Entity Framework Core
    ├── Models            # Основные сущности системы
    ├── ViewModels        # Модели представления
    ├── Views             # Razor-представления
    ├── wwwroot           # Стили, скрипты и статические ресурсы
    ├── Program.cs        # Конфигурация приложения
    └── appsettings.json  # Параметры приложения
```

## Основные сущности

В базе данных используются следующие основные сущности:

* `User` - учётная запись пользователя;
* `StudentProfile` - профиль студента;
* `DocumentType` - тип доступного документа;
* `DocumentRequest` - заявка студента;
* `RequestComment` - комментарий или уточнение;
* `RequestStatusHistory` - история изменения статусов.

Между сущностями настроены связи, позволяющие хранить заявки студентов, назначать ответственных сотрудников и отслеживать полный жизненный цикл обращения.

## Состояния заявки

Заявка проходит несколько этапов обработки:

```text
Создана
   ↓
В работе
   ↓
Готова
```

Также заявка может быть отклонена, если указаны некорректные сведения или отсутствуют необходимые основания для подготовки документа.

Каждое изменение сохраняется в истории обработки.

## Установка и запуск

### Требования

Для локального запуска необходимы:

* .NET 10 SDK;
* MySQL Server;
* Git;
* Visual Studio 2022 / 2026, JetBrains Rider или Visual Studio Code.

### 1. Клонирование репозитория

```bash
git clone https://github.com/penaps32/EduDocFlow.git
cd EduDocFlow
```

### 2. Создание базы данных

Создайте пустую базу данных MySQL:

```sql
CREATE DATABASE edudocflow
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

### 3. Настройка подключения

Рекомендуется сохранить строку подключения через .NET User Secrets:

```bash
dotnet user-secrets set \
  "ConnectionStrings:DefaultConnection" \
  "Server=localhost;Port=3306;Database=edudocflow;User=root;Password=YOUR_PASSWORD;" \
  --project WebApplication1/EduDocFlow.Web.csproj
```

Вместо `YOUR_PASSWORD` укажите пароль пользователя MySQL.

Также строку подключения можно временно указать в файле `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Port=3306;Database=edudocflow;User=root;Password=YOUR_PASSWORD;"
  }
}
```

Не публикуйте настоящий пароль от базы данных в открытом репозитории.

### 4. Восстановление зависимостей

```bash
dotnet restore WebApplication1/EduDocFlow.Web.csproj
```

### 5. Запуск приложения

```bash
dotnet run --project WebApplication1/EduDocFlow.Web.csproj
```

При первом запуске приложение автоматически:

* применит миграции базы данных;
* создаст демонстрационные учётные записи;
* заполнит справочник типов документов.

Адрес приложения будет выведен в терминале после запуска.

| Студент       | `student@edudoc.local`   | `Student123!`   |

| Администратор | `admin@edudoc.local`     | `Admin123!`     |

Эти данные предназначены только для локального запуска и демонстрации проекта.
